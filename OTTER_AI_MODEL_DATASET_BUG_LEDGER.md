| **`AI-BUG-009`** | Worker Governor Concurrency Decay (`32 -> 1`) Under Synchronous `fsync` Contention | [`crates/gui/scripts/ai_engine.py`](crates/gui/scripts/ai_engine.py) | During the initial `ollama pull qwen2.5:1.5b` run (`986 MB`), `AdaptiveWorkerGovernor` decayed from `32 -> 18 -> 13 -> 9 -> 6 -> 4 -> 3 -> 2 -> 1` worker. | Calling synchronous `os.fsync(part_fd.fileno())` inside `file_io_lock` after every single `8 MiB` segment serialized all 32 worker threads behind NTFS flush latency (`>80ms`), triggering repeated `disk_write_pressure` reductions while `progress_cb` only fired at `8 MiB` segment boundaries. | Moved `progress_cb(len(chunk))` to fire per `256 KiB` network read chunk for smooth real-time goodput measurement, batched `os.fsync` to batch boundaries while keeping `part_fd.flush()` per segment, and set `min_workers = 8` with adaptive probing. | **VERIFIED** (`qwen2.5:1.5b` dynamic worker scaling verified) |
| **`AI-BUG-010`** | In-Flight Segment Retransmission on Mid-Segment Interruption | [`crates/gui/scripts/ai_engine.py`](crates/gui/scripts/ai_engine.py) | When an interruption (`stop_at_fraction` or pause) occurred while 8 parallel workers were mid-way through `2 MiB` segments, in-flight buffers (`buf`) were discarded rather than flushed, causing partially read segment prefixes to be re-requested on resume. | `download_one_segment` returned `False` on `stopped_early` without flushing `buf` to `part_fd` or advancing `seg["start"] = start_b + len(buf)`. | Added sub-segment partial checkpointing on `stopped_early`: any bytes already received in `buf` are written at `start_b`, flushed to `part_fd`, and `seg["start"]` is advanced to `start_b + len(buf)` (`orig_start` preserved for byte accounting), reducing `retransmitted_checkpointed_bytes` to `0` bytes across all checkpoints (`10%, 30%, 50%, 80%, 90%`). | **VERIFIED** (`0` bytes retransmitted across all 5 checkpoints) |
| **`AI-BUG-011`** | TCP Bufferbloat & RTT Inflation at 96 Workers on Residential Link | [`crates/gui/scripts/ai_engine.py`](crates/gui/scripts/ai_engine.py) | Scaling a single download up to `96` concurrent connections on a `~2.5-3.0 MB/s` residential link inflated HTTP RTT from `50 ms` to `3,422-5,369 ms` (`5.37s`), adding TLS handshake overhead on unthrottled single archives. | `AdaptiveWorkerGovernor.evaluate()` did not penalize high RTT (`avg_rtt_ms > 450 ms`) when scaling workers upward. | Added an RTT bufferbloat guard (`avg_rtt_ms > 450.0` trims worker count by `25%` down to the optimal `12-24` sweet spot and caps `max_workers` at `48`), reducing peak RTT from `5,369 ms` to `462-779 ms` and improving `wine-reviews` download time from `10.773s` (`1.65 MB/s`) to `8.276s` (`2.14 MB/s` avg, `8.02 MB/s` peak). | **VERIFIED** (`rtt_bufferbloat_guard` active; download time reduced by `23.2%`) |
